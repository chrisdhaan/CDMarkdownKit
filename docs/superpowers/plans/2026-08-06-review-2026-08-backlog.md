### Task 1: Fix catastrophic-backtracking regex in `CDMarkdownCode` and `CDMarkdownSyntax`

**Files:**
- Modify: `Source/CDMarkdownCode.swift:38`
- Modify: `Source/CDMarkdownSyntax.swift:38`
- Test: `Tests/CDMarkdownKitTests/Elements/CDMarkdownCodeTests.swift`
- Test: `Tests/CDMarkdownKitTests/Elements/CDMarkdownSyntaxTests.swift`

**Interfaces:** None — self-contained, no dependency on other tasks. (Task 2 depends on this task landing first, since it edits the same file.)

**Background:** Both regexes contain a content-capture group with overlapping quantifiers — `\s*[^\`]*?\s*` — where `\s` is a subset of the `[^\`]` character class. On an unterminated backtick span (no closing delimiter ahead in the string), the regex engine has combinatorially many ways to partition the same run of characters across the three quantified pieces before failing — classic catastrophic backtracking. Since `\s` is already contained within `[^\`]`, the two `\s*` bookends are semantically redundant: `[^\`]*` alone already matches everything (including whitespace and newlines) up to the next backtick, because the content can never legitimately contain a backtick. Removing the redundant bookends preserves every matching case identically (same captured text) while eliminating the backtracking blow-up on non-matching (unterminated) input.

### Task 4: Fix `CDMarkdownList` counting blank lines as indentation

**Files:**
- Modify: `Source/CDMarkdownList.swift:38`
- Test: `Tests/CDMarkdownKitTests/Elements/CDMarkdownListTests.swift`

**Interfaces:** None — self-contained.

**Background:** The indentation-capture group is `(\s*)`, which (combined with `.anchorsMatchLines`) can swallow blank lines' newline characters preceding a list item into the "indent" string, since `\s` includes `\n`. `indentLevel(for:)` then miscounts those swallowed newlines as ordinary padding, nesting a top-level list item that has no real indentation. `CDMarkdownQuote.swift` avoids this exact problem by using `[ \t]*` for its own leading-whitespace handling — this fix applies the same character class to List's capture group (kept as a capture group, since List, unlike Quote, uses the captured indent string later to compute nesting depth).

**Important trigger-condition correction found while planning this task:** the review's original repro assumed the bug fires under fully-default settings. It doesn't — `squashNewlines` (default `true`) collapses any run of 2+ newlines to a single `\n` *before* `CDMarkdownList`'s regex ever runs, which erases the very blank-line run this bug depends on. The bug is real and still worth fixing, but only reproduces when `squashNewlines` is explicitly set to `false` — a supported, non-default configuration (see `CDMarkdownSquashNewlinesTests.swift`). The regression test below sets `squashNewlines = false` accordingly.
